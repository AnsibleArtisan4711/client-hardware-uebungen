# 08.1 Configuration Manager: Aufbau

| | |
|---|---|
| **Modul** | 08 Configuration Manager: Aufbau (Priorität 1) |
| **Stufe** | Vertiefung |
| **Geschätzte Zeit** | 4 bis 7 Stunden (Schätzung; Lehrplan: 8 UE zu 45 Minuten = 6,00 Stunden) |
| **Werkzeuge** | Configuration-Manager-Setup, SQL Server 2022, Windows ADK, Windows-Firewall, Konsole von Configuration Manager |
| **Vorwissen** | Modul 06 (`DEPLOY01` im Zustand `DEPLOY01-M6-Ende`, also ohne WDS) |

> [!WARNING]
> **Stand der Prüfung: Entwurf, nicht im Labor ausgeführt.** Dieses Modul ist **nicht ausgeführt** und hängt von einer lauffähigen Installation ab. Die Versionsangaben (2609, Build 5.00.9152.1000, Supportende 28.03.2028) stammen aus dem Lehrplan (Learn-Suchtreffer vom 08.11.2026). Die Verfügbarkeit einer Evaluation von Configuration Manager 2609, die Windows-Funktionsnamen, `ccmsetup`-Parameter, Konsolenbezeichnungen und die Dauer der Installation sind *nicht bestätigt*. Die Learn-Laborseite ist veraltet (nennt Windows Server 2012 R2 und SQL Server 2012) und wird nur für die Abfolge der Schritte benutzt. Fällt die Installation aus, startet der Kursleiter mit der Ausweich-VM `DEPLOY01-CM-fertig` bei Teil 4. Notiere jede Abweichung, die du im Labor beobachtest.

## Lernziele

Nach dieser Übung kannst du

- die Architektur eines Standorts (Standortserver, Datenbank, Verwaltungspunkt, Verteilungspunkt, SMS Provider) erklären und Bezeichnungen und Versionsstand mit Datum wiedergeben,
- die Voraussetzungen (SQL-Server-Version und Sortierung, ADK, Konten, Ports) prüfen und herstellen,
- einen eigenständigen Primärstandort `LAB` installieren und die Konsole öffnen,
- Grenzen, Erkennung und die Client-Installation einrichten und prüfen.

## Voraussetzungen

- Modul 06 abgeschlossen: `DEPLOY01` zurückgesetzt auf `DEPLOY01-M6-Ende` (ohne WDS).
- ADK 10.1.26100.9457 und Windows-PE-Add-on sind installiert (aus Modul 03, im Prüfpunkt enthalten).
- Offline-Medien: SQL Server 2022, Microsoft ODBC Driver for SQL Server, Installationsmedium von Configuration Manager mit Prerequisite Downloads.
- Kennwörter vergibt der Kursleiter; sie stehen in keinem Dokument.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Standort (Site)** | Verwaltungseinheit von Configuration Manager; hier ein eigenständiger Primärstandort mit Code `LAB`. |
| **Standortserver** | Server, auf dem der Standort installiert ist. |
| **Standortdatenbank** | SQL-Server-Datenbank mit allen Daten des Standorts. |
| **SMS Provider** | Schnittstelle zwischen Konsole und Datenbank. |
| **Verwaltungspunkt** | Anlaufstelle der Clients für Richtlinien und Berichte. |
| **Verteilungspunkt** | Server, der Inhalte (Abbilder, Anwendungen) und PXE bereitstellt. |
| **Grenze / Grenzgruppe** | Netzbereich, dem Clients zugeordnet werden; die Grenzgruppe verknüpft Grenzen mit Standort und Inhaltsstandorten. |
| **Prerequisite Checker** | Prüfung der Voraussetzungen vor der Installation. |

## Aufgabe

### Teil 1: Architektur und Versionswahl

*(Lerneinheit 8.1, Praxisaufgabe 1)*

1. Ordne in einer Tabelle jeder Rolle (Standortserver, Standortdatenbank, SMS Provider, Verwaltungspunkt, Verteilungspunkt) den Server im Labor zu (alle auf `DEPLOY01`) und begründe, warum Learn die Trennung als bewährte Praxis nennt.
2. Wähle die Version (Vorschlag: 2609, Build 5.00.9152.1000, verfügbar seit 28.09.2026, Supportende 28.03.2028, Baseline „ja“). Prüfe und notiere: Windows Server 2025 als Standortserver (laut Learn unterstützt), SQL Server 2022 (laut Learn unterstützt), ADK 10.1.26100.9457 (laut Matrix unterstützt).
3. Nenne die Bezeichnung des Produkts mit Stand und kennzeichne, was nicht geprüft ist (Umbenennungsdaten).

### Teil 2: Voraussetzungen herstellen

*(Lerneinheit 8.2, Praxisaufgabe 2)*

Auf `DEPLOY01`:

1. Windows-Funktionen installieren: .NET Framework 3.5 und Remote Differential Compression (beide laut Learn Voraussetzung des Standortservers). Die Funktionsnamen sind *nicht bestätigt*:

   ```powershell
   Install-WindowsFeature -Name NET-Framework-Core -Source D:\sources\sxs
   Install-WindowsFeature -Name RDC
   Get-WindowsFeature NET-Framework-Core, RDC | Format-Table Name, InstallState
   ```

   Der Quellpfad `D:\sources\sxs` ist ein Beispiel für eine eingebundene Server-ISO.
2. ADK samt Windows-PE-Add-on prüfen (Version notieren).
3. Microsoft ODBC Driver for SQL Server und SQL Server 2022 installieren: eigene Instanz, Windows-Authentifizierung, Sortierung `SQL_Latin1_General_CP1_CI_AS`, Dienstkonto mit niedrigen Rechten. Die Learn-Laborseite nennt keine Begrenzung des SQL-Arbeitsspeichers; die Praxisfolgen sind *nicht bestätigt*.
4. Firewall: Öffne die Ports 1433 (Datenbank) und 4022 (Service Broker), laut Learn-Laborseite:

   ```powershell
   New-NetFirewallRule -DisplayName "SQL 1433 (Lab)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
   New-NetFirewallRule -DisplayName "SQL Service Broker 4022 (Lab)" -Direction Inbound -Protocol TCP -LocalPort 4022 -Action Allow
   ```

5. Aktiviere für die Installation den Dienst „Remote Registry“ (laut Learn).
6. Führe den Prerequisite Checker aus und dokumentiere Warnungen und Fehler.

Die Erweiterung des Active-Directory-Schemas wird im Labor **nicht** durchgeführt (optional; die Folgen für die Standortveröffentlichung sind *nicht bestätigt*).

### Teil 3: Standort installieren

*(Lerneinheit 8.3, Praxisaufgabe 3)*

Führe den Setup-Assistenten aus (Schritte nach der Learn-Laborseite):

- Produktschlüssel „Evaluation“ (wenn verfügbar, sonst nach Anweisung des Kursleiters),
- „Download required files“ mit dem Pfad der Offline-Medien,
- Standortcode `LAB`, Standortname frei, eigenständiger Primärstandort,
- Datenbank auf `DEPLOY01` (Standardinstanz, Port 4022),
- SMS Provider und Verwaltungspunkt auf `DEPLOY01`,
- Kommunikation der Clients **nicht** auf HTTPS beschränkt (nur im isolierten Labor; HTTPS/PKI ist hier Out of Scope).

Prüfe nach der Installation Dienste und Protokolle (Serverprotokolle laut Learn unter `C:\Program Files\Microsoft Configuration Manager\Logs`; `ConfigMgrSetup.log` liegt nach Erfahrung im Stamm von `C:\`, *nicht bestätigt*) und öffne die Konsole. Notiere die Dauer der Installation (unerprobt).

### Teil 4: Grenzen, Erkennung, Client

*(Lerneinheit 8.4, Praxisaufgabe 4)*

1. Lege eine **Grenze** (IP-Adressbereich `10.70.0.1` bis `10.70.0.254`) und eine **Grenzgruppe** `BG-Lab` mit Standortzuweisung und Inhaltsstandort `DEPLOY01` an.
2. Aktiviere die Active-Directory-Systemerkennung für `OU=Rollout,DC=lab,DC=example,DC=internal`.
3. Installiere den Client auf `DEPLOY01`, zum Beispiel über die Konsole oder mit
   `ccmsetup.exe /mp:DEPLOY01.lab.example.internal SMSSITECODE=LAB` (Parameter *nicht bestätigt*). Prüfe, dass `DEPLOY01` als „Client: Ja“ und „Aktiv“ erscheint (Bezeichnungen *nicht bestätigt*) und die Protokolle unter `C:\Windows\CCM\Logs` liegen.
4. Beschreibe, warum Grenzgruppen wichtig sind. Hinweis: Eine Korrektur in Version 2609 behebt, dass ein Gerät in Windows PE zu einem Verwaltungspunkt außerhalb seiner Grenzgruppe wechseln konnte.
5. Fahre beide VMs herunter und lege die Prüfpunkte `DC01-M8-Ende` und `DEPLOY01-M8-Ende` an. Setze sie später nur **gemeinsam** zurück.

## Hinweise

- Alle Rollen auf einem Server sind nur für das Labor gedacht. Im Betrieb trennt man Datenbank und Standortserver und plant mehrere Verteilungspunkte.
- Ist die Installation nach längerer Zeit nicht fertig, prüfe `ConfigMgrSetup.log` und frage den Kursleiter nach der Ausweich-VM.
- `DC01` wird nach Modul 08 nicht allein zurückgesetzt, weil Computerkonten und Veröffentlichungen sonst nicht mehr zusammenpassen.
- SQL Server 2016 wird laut Learn ab Version 2609 nicht mehr unterstützt (Lehrplan, Kontrollwerte).
- Domänenname, Domänenmitgliedschaft und Computername eines Standortsystems dürfen nach der Installation nicht mehr geändert werden (laut Learn zuvor Rolle entfernen).

2. Wie heißt das Produkt in der aktuellen Dokumentation, wie hieß es früher, und was ist über die Umbenennungsdaten bekannt?
3. Welche SQL-Server-Versionen unterstützt Version 2609, und welche nicht mehr?
4. Was ist laut Learn nach der Installation eines Standortsystems nicht mehr unterstützt zu ändern?
5. Wozu dienen Grenzen und Grenzgruppen?

**Zielzustand:** Standort `LAB` installiert, Konsole geöffnet, Grenzgruppe `BG-Lab`, Erkennung aktiv, Client auf `DEPLOY01` aktiv; Prüfpunkte `DC01-M8-Ende` und `DEPLOY01-M8-Ende`.

**Teil 1 (Tabelle):** Standortserver, Standortdatenbank, SMS Provider, Verwaltungspunkt und Verteilungspunkt liegen im Labor alle auf `DEPLOY01`. Learn nennt die Trennung als bewährte Praxis, weil Ausfall, Last und Sicherheit der Rollen unabhängig voneinander behandelt werden können.

**Kontrollfragen**

1. Standortserver, Datenbank, SMS Provider, Verwaltungspunkt, Verteilungspunkt. Im Betrieb ist das ein Ausfall- und Lastrisiko, und Rollen können sich Ressourcen wegnehmen.
2. Aktuell *Configuration Manager* bzw. *Microsoft Configuration Manager (current branch)*; früher *Microsoft Endpoint Configuration Manager* (MECM) und davor SCCM. Die Umbenennungsdaten sind nicht geprüft.
3. SQL Server 2017 (ab CU2), 2019 (ab CU5), 2022 und 2025 (Unterstützung ab 2603); SQL Server 2016 wird ab 2609 nicht mehr unterstützt.
4. Domänenname, Domänenmitgliedschaft und Computername dürfen nach der Installation nicht geändert werden.
5. Grenzen beschreiben Netzbereiche, Grenzgruppen ordnen sie Standort und Inhaltsstandorten zu. Clients finden dadurch ihre Verwaltungspunkte und Verteilungspunkte.
