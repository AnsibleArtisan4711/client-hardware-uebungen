## Lernziele

Nach dieser Übung kannst du

- eine UEFI/GPT-Partitionierung mit `diskpart` erstellen und jede Zeile erklären,
- ein WIM-Abbild aus Windows PE anwenden und mit `bcdboot` startfähig machen,
- eine Antwortdatei den Konfigurationsphasen zuordnen und auf Wohlgeformtheit und Schema prüfen,
- eine skriptgesteuerte Bereitstellung aus Windows PE aufbauen und deren Sicherheitsrisiken benennen.

## Voraussetzungen

- Modul 03 abgeschlossen: `E:\Images\W11-ENT-Basis.wim` und `E:\Images\WinPE-Basis.iso` vorhanden.
- Ordner `E:\Images\scripts` angelegt.
- Hinweis: Die Antwortdatei wurde im Kurs Windows-11-Client-Administration einführend behandelt. Die Wiederholung ist gewollt, hier mit Schwerpunkt Rollout.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **EFI-Systempartition (ESP)** | FAT32-Partition mit den Startdateien einer UEFI-Installation. |
| **MSR** | Microsoft Reserved Partition, 16 MB, von Windows intern reserviert. Wird ohne Laufwerksbuchstaben angelegt. |
| **`bcdboot`** | Kopiert Startdateien aus dem Windows-Ordner auf die Systempartition und legt die Startkonfiguration (BCD) an. |
| **`Autounattend.xml`** | Antwortdatei für Windows Setup (Phase `windowsPE` und folgende). |
| **`unattend.xml`** | Antwortdatei, die ein bereits angewendetes Abbild beim ersten Start liest (Phasen `specialize`, `oobeSystem`). |
| **Konfigurationsphase** | Abschnitt des Setups: `windowsPE`, `specialize`, `oobeSystem` (weitere siehe Learn). |
| **Panther** | Ordner `Windows\Panther`, in dem Setup Protokolle und die zwischengespeicherte Antwortdatei ablegt. |

## Aufgabe

### Teil 1: Partitionierung

*(Lerneinheit 4.1, Praxisaufgabe 1)*

Vervollständige das Skript (Datei `dateien/CreatePartitions-UEFI.txt`; hier ist die Größe der MSR-Partition mit `???` ausgelassen) und erkläre jede Zeile in einem Satz.

```text
select disk 0
clean
convert gpt
create partition efi size=300
format quick fs=fat32 label="System"
assign letter=S
create partition msr size=???
create partition primary
format quick fs=ntfs label="Windows"
assign letter=W
```

Das Skript ist an die Learn-Beispielskripte für UEFI/GPT angelehnt. Prüfe nach dem Lauf mit `list partition` und `list volume`, dass drei Partitionen vorhanden sind. Eine Wiederherstellungspartition (WinRE) entfällt in diesem Lab-Layout; die Folgen für Windows RE sind nicht geprüft.

### Teil 2: Antwortdatei prüfen

*(Lerneinheit 4.3, Praxisaufgabe 2)*

Lies `dateien/unattend-CL01.xml` (Phasen `specialize` und `oobeSystem`, für den Einsatz nach `Apply-Image`) und ordne jede Einstellung einer Phase zu: Computername, Zeitzone, Sprachen, OOBE-Optionen, lokales Konto `labadmin`.

1. Prüfe die Wohlgeformtheit (`xmllint --noout datei.xml` unter Linux oder `[xml]$x = Get-Content -Raw datei.xml` in PowerShell).
2. Öffne die Datei im Windows System Image Manager mit einem Katalog der Enterprise-Edition und validiere sie. Das Schema wird **nur dort** geprüft.
3. Beschreibe in zwei Sätzen, was eine `Autounattend.xml` mit der Phase `windowsPE` (Partitionierung, Abbildauswahl) leistet und warum sie bei `Apply-Image` keine Rolle spielt.

Das Kennwort steht als Platzhalter `PLATZHALTER-vom-Kursleiter` in der Datei. Setze das echte Kennwort nur in einer Arbeitskopie ein, die nie im Repository liegt.

### Teil 3: Abbild anwenden

*(Lerneinheit 4.2, Praxisaufgabe 3)*

Lege die Dateien aus `dateien/` nach `E:\Images\scripts` (`unattend-CL01.xml`, `CreatePartitions-UEFI.txt`). Starte `CL01` mit dem WinPE-ISO und führe aus:

```cmd
net use Z: \\DEPLOY01\Images /user:LAB\svc-osd-read
diskpart /s Z:\scripts\CreatePartitions-UEFI.txt
dism /Apply-Image /ImageFile:Z:\W11-ENT-Basis.wim /Index:1 /ApplyDir:W:\
mkdir W:\Windows\Panther
copy Z:\scripts\unattend-CL01.xml W:\Windows\Panther\unattend.xml
bcdboot W:\Windows /s S: /f UEFI
wpeutil reboot
```

Entferne danach das ISO (`Set-VMDvdDrive -VMName CL01 -Path $null`) und stelle die Festplatte als erstes Startgerät ein. Beobachte den ersten Start: Wird die Antwortdatei gelesen (Computername `CL01`, kein Konto-Dialog)? Dokumentiere Abweichungen.

### Teil 4: Skript und Sicherheit

*(Lerneinheit 4.4, Praxisaufgabe 4)*

Lies `dateien/Deploy.cmd`. Das Skript fasst die Schritte aus Teil 3 zusammen und fragt das Kennwort ab (`*`). Rufe es in WinPE von Hand auf. Beantworte schriftlich:

1. Welche **drei Risiken** entstehen, wenn Kennwort und Skript im Boot-Abbild stehen?
2. Nenne **zwei Gegenmaßnahmen**.

## Hinweise

- `clean` löscht die gesamte Platte. Führe das Skript nur in den leeren Labor-VMs aus.
- Die Laufwerksbuchstaben in WinPE sind nicht fest. Prüfe sie mit `list volume`, bevor du `/ApplyDir` angibst. `X:` ist in WinPE belegt.
- Fehlt die Startdatei, meldet die VM nach dem Neustart, dass kein Startmedium gefunden wurde. Prüfe dann `bcdboot` und die Startreihenfolge.
- Ob die Antwortdatei unter `Panther` automatisch gelesen wird, ist *nicht bestätigt*. Notiere das Ergebnis mit Windows-Version.
- Skripte mit `*` bei `net use` fragen das Kennwort ab, es bleibt nicht in der Datei.

## Kontrollfragen

1. Wozu dient die MSR-Partition, und warum braucht eine UEFI-Installation eine EFI-Systempartition im Format FAT32?
2. Warum reicht `Apply-Image` allein nicht, und was erledigt `bcdboot`?
3. In welcher Phase stehen Partitionierung, Computername und Benutzerkonto (`windowsPE`, `specialize`, `oobeSystem`)?
4. Warum führt `Apply-Image` die Phase `windowsPE` einer `Autounattend.xml` nicht aus?
5. Warum ist ein Kennwort im Boot-Abbild von jedem Gerät im Netz auslesbar, das per PXE starten darf?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand:** `CL01` startet von der Platte mit angewendetem Abbild; Partitionierung mit EFI (300 MB, FAT32), MSR (16 MB) und Windows (NTFS); `Deploy.cmd` liegt auf der Freigabe und läuft von Hand.

**Teil 1:** MSR 16 MB. Erwartet: drei Partitionen. `select disk 0` wählt die Platte, `clean` löscht sie, `convert gpt` stellt auf GPT um, die weiteren Zeilen legen ESP, MSR und Windows-Partition an und vergeben Buchstaben für `bcdboot` und `Apply-Image`.

**Teil 2:** `specialize`: Computername, Zeitzone (ein Einsatz in `oobeSystem` ist ebenfalls möglich, nicht bestätigt). `oobeSystem`: Sprachen, OOBE-Optionen, lokales Konto. Eine `Autounattend.xml` mit `windowsPE` kann Partitionierung und Abbildauswahl vorgeben; bei `Apply-Image` läuft Windows Setup nicht, deshalb wird die Phase nicht ausgeführt.

**Teil 4 (Beispielantworten):** Risiken: (1) Das Kennwort ist im Abbild für jeden lesbar, der es laden darf; (2) das Abbild ist für jedes Gerät mit PXE ladbar; (3) ein fremder DHCP/PXE-Server kann ein manipuliertes Abbild liefern. Gegenmaßnahmen: Kennwort abfragen statt speichern, ein Konto mit nur Leserechten (`svc-osd-read`) verwenden; PXE nur mit Kennwort oder für bekannte Geräte erlauben.

**Kontrollfragen**

1. Die MSR-Partition ist ein reservierter Bereich für Windows. Die UEFI-Firmware kann nur FAT-Dateisysteme lesen, deshalb ist die ESP FAT32.
2. `Apply-Image` kopiert nur die Dateien. Es fehlen Startdateien und BCD. `bcdboot` legt sie auf der Systempartition aus dem Windows-Ordner an.
3. Partitionierung: `windowsPE`. Computername: `specialize`. Benutzerkonto: `oobeSystem`.
4. Windows Setup läuft bei `Apply-Image` nicht. Die Phase `windowsPE` gehört zu Setup.
5. Das Boot-Abbild wird per TFTP an jeden geliefert, der anfragt. Ein Kennwort darin kann jeder auslesen (Abbild mounten und Dateien ansehen).

</details>
