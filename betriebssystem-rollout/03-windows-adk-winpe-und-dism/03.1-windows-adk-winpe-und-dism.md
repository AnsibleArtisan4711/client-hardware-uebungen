Die Komponenten, ihre Reihenfolge, der Standardpfad und die Sprachdateien in `en-us` sind laut Learn-Seite *WinPE Optional Components Reference* belegt; der Ablauf in der VM (Secure Boot, Startreihenfolge) ist *nicht bestätigt*. ## Lernziele

Nach dieser Übung kannst du

- die Aufgabe von ADK, Windows PE und Windows-PE-Add-on erklären und die passende ADK-Version begründen,
- ein Windows-PE-Medium bauen, um optionale Komponenten erweitern und in einer VM starten,
- mit DISM ein Abbild untersuchen, mounten und exportieren,
- WIM, VHDX und FFU unterscheiden und die Einfachspeicherung gleicher Dateien in einer WIM erklären.

## Voraussetzungen

- Modul 02 abgeschlossen; `DEPLOY01` ist in der Domäne, `E:\Images` ist freigegeben, `CL01` ist leer.
- Offline-Medien: ADK 10.1.26100.9457 samt Windows-PE-Add-on, ISO Windows 11 Enterprise (Evaluation).
- Anmeldung auf `DEPLOY01` als `LAB\labadmin`.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **ADK** | Windows Assessment and Deployment Kit: Werkzeuge für Bereitstellung. Die Funktion *Deployment Tools* ist das Minimum für WinPE-Medien. |
| **Windows PE (WinPE)** | Kleines Betriebssystem zum Installieren, Erfassen und Reparieren. Seit Windows 10, Version 1809, ein eigenes Add-on zum ADK. |
| **`copype`** | Legt ein Arbeitsverzeichnis mit den WinPE-Dateien an (`media`, `mount`, `boot.wim`). |
| **`MakeWinPEMedia`** | Erzeugt aus dem Arbeitsverzeichnis ein startfähiges Medium (`/ISO` oder `/UFD`). |
| **Optionale Komponente** | `.cab`-Paket, das WinPE um eine Funktion erweitert (WMI, .NET, PowerShell). |
| **Index** | Nummer eines Abbilds in einer WIM-Datei. |
| **Einfachspeicherung** | Gleiche Dateien werden in einer WIM nur einmal gespeichert. |
| **WIM / VHDX / FFU** | WIM: dateibasiert. VHDX: virtuelle Festplatte. FFU: sektorbasiertes Abbild einer ganzen Platte. |

### Teil 2: WinPE bauen und starten

*(Lerneinheit 3.2, Praxisaufgabe 2)*

Öffne die *Deployment and Imaging Tools Environment* als Administrator (Name des Startmenüeintrags *nicht bestätigt*) und baue das Arbeitsverzeichnis. Das Zielverzeichnis darf noch nicht existieren.

```cmd
copype amd64 E:\WinPE\amd64
Dism /Mount-Image /ImageFile:"E:\WinPE\amd64\media\sources\boot.wim" /Index:1 /MountDir:"E:\WinPE\amd64\mount"
set OC=C:\Program Files (x86)\Windows Kits\10\Assessment and Deployment Kit\Windows Preinstallation Environment\amd64\WinPE_OCs
Dism /Image:"E:\WinPE\amd64\mount" /Add-Package /PackagePath:"%OC%\WinPE-WMI.cab"
Dism /Image:"E:\WinPE\amd64\mount" /Add-Package /PackagePath:"%OC%\en-us\WinPE-WMI_en-us.cab"
Dism /Image:"E:\WinPE\amd64\mount" /Add-Package /PackagePath:"%OC%\WinPE-NetFx.cab"
Dism /Image:"E:\WinPE\amd64\mount" /Add-Package /PackagePath:"%OC%\en-us\WinPE-NetFx_en-us.cab"
Dism /Image:"E:\WinPE\amd64\mount" /Add-Package /PackagePath:"%OC%\WinPE-Scripting.cab"
Dism /Image:"E:\WinPE\amd64\mount" /Add-Package /PackagePath:"%OC%\en-us\WinPE-Scripting_en-us.cab"
Dism /Image:"E:\WinPE\amd64\mount" /Add-Package /PackagePath:"%OC%\WinPE-PowerShell.cab"
Dism /Image:"E:\WinPE\amd64\mount" /Add-Package /PackagePath:"%OC%\en-us\WinPE-PowerShell_en-us.cab"
Dism /Unmount-Image /MountDir:"E:\WinPE\amd64\mount" /Commit
MakeWinPEMedia /ISO E:\WinPE\amd64 E:\Images\WinPE-Basis.iso
```

`copype` und `MakeWinPEMedia` sind auf Learn belegt. Ebenfalls laut Learn (*WinPE Optional Components Reference*): Der Standardpfad der Komponenten ist der gezeigte (bei anderem Installationsort anpassen); jede Komponente braucht zuerst ihre sprachneutrale `.cab` und dann die Sprachdatei in `en-us`; die **Reihenfolge der Abhängigkeiten** für PowerShell lautet `WinPE-WMI` > `WinPE-NetFX` > `WinPE-Scripting` > `WinPE-PowerShell`. Wer später Windows Setup aus WinPE starten will, braucht laut Learn zusätzlich `WinPE-WMI` und `WinPE-SecureStartup`. Lasse bei Fehlern `Dism /Unmount-Image … /Discard` laufen, bevor du neu beginnst.

Danach:

1. Übertrage das ISO mit `Copy-Item -FromSession` nach `D:\ISO\WinPE-Basis.iso`.
2. Auf dem Host: `Add-VMDvdDrive -VMName CL01 -Path D:\ISO\WinPE-Basis.iso`, dann `Set-VMFirmware -VMName CL01 -FirstBootDevice (Get-VMDvdDrive -VMName CL01)` und `Start-VM CL01`.
3. In WinPE: `ipconfig` und prüfe, ob `CL01` eine Adresse aus `10.70.0.100` bis `10.70.0.199` hat.
4. Auf `DC01`: `Get-DhcpServerv4Lease -ScopeId 10.70.0.0` und prüfe, ob die Vergabe erscheint.
5. Startet das ISO bei aktivem Secure Boot nicht, prüfe die Secure-Boot-Vorlage der VM. Die Ursache ist *nicht bestätigt*; dokumentiere die Beobachtung.

Wer das ISO als Version mit der neueren Zertifikatskette bauen muss, findet bei `MakeWinPEMedia` die Option `/bootex` (ab ADK 10.1.26100.2454, laut Learn). Ob das für dein Labor nötig ist, ist *nicht bestätigt*.

### Teil 3: Abbild untersuchen und exportieren

*(Lerneinheit 3.3, Praxisaufgabe 3)*

1. Hänge die Windows-11-Enterprise-ISO an `DEPLOY01`. Lies Editionen und Indizes aus:

   ```cmd
   Dism /Get-ImageInfo /ImageFile:<Laufwerk>:\sources\install.wim
   ```

   Liegt statt `install.wim` eine `install.esd` vor, gilt der Befehl mit diesem Dateinamen (*nicht bestätigt*). Notiere Namen und **Index** der Edition Enterprise.
2. Exportiere diese Edition in eine eigene Datei und vergleiche die Größen:

   ```cmd
   Dism /Export-Image /SourceImageFile:<Laufwerk>:\sources\install.wim /SourceIndex:<n> /DestinationImageFile:E:\Images\W11-ENT-Basis.wim
   Dism /Get-ImageInfo /ImageFile:E:\Images\W11-ENT-Basis.wim
   ```

### Teil 4: Einfachspeicherung testen

*(Lerneinheit 3.4, Praxisaufgabe 4)*

Erzeuge **Zufallsdateien**. `fsutil file createnew` schreibt nur Nullbytes: Gleich große Nulldateien wären untereinander Duplikate und würden den Test verfälschen.

```powershell
New-Item -ItemType Directory E:\Test\s1, E:\Test\s2 | Out-Null
$rnd = New-Object System.Random
$b = New-Object byte[] 20000000; $rnd.NextBytes($b); [IO.File]::WriteAllBytes("E:\Test\s1\common.bin", $b)
Copy-Item E:\Test\s1\common.bin E:\Test\s2\common.bin
$b = New-Object byte[] 5000000;  $rnd.NextBytes($b); [IO.File]::WriteAllBytes("E:\Test\s1\u1.bin", $b)
$b = New-Object byte[] 5000000;  $rnd.NextBytes($b); [IO.File]::WriteAllBytes("E:\Test\s2\u2.bin", $b)
```

Erfasse `s1` und `s2` je in eine **eigene** WIM-Datei und danach beide als Index 1 und 2 in **eine** WIM-Datei:

```cmd
Dism /Capture-Image /ImageFile:E:\Test\s1.wim /CaptureDir:E:\Test\s1 /Name:s1 /Compress:none
Dism /Capture-Image /ImageFile:E:\Test\s2.wim /CaptureDir:E:\Test\s2 /Name:s2 /Compress:none
Dism /Capture-Image /ImageFile:E:\Test\beide.wim /CaptureDir:E:\Test\s1 /Name:s1 /Compress:none
Dism /Append-Image  /ImageFile:E:\Test\beide.wim /CaptureDir:E:\Test\s2 /Name:s2
```

Vergleiche die Dateigrößen (`Get-Item E:\Test\*.wim | Select Name, Length`) und erkläre den Unterschied.

## Hinweise

- `copype` verweigert ein bereits vorhandenes Zielverzeichnis. Lösche es oder wähle einen neuen Namen.
- Bleibt ein Abbild nach einem Fehler gemountet, hilft `Dism /Cleanup-Wim` (*nicht bestätigt*) oder `Dism /Unmount-Image … /Discard`. Gemountete Abbilder blockieren den Ordner.
- Der Pfad zu `.cab`-Dateien im ADK ist je nach Installationsort verschieden. Suche ihn mit `Get-ChildItem -Recurse -Filter WinPE-WMI.cab` unter dem ADK-Ordner.
- Ein Windows-PE-Medium enthält nach `MakeWinPEMedia` das Boot-Abbild `boot.wim`. Alles, was du später im Boot-Abbild änderst, braucht ein neues ISO (Modul 06).
- Die Zahlen aus Teil 4 weichen bei DISM durch Metadaten von denen aus `wimlib` ab. Prüfe, ob die Größenordnung stimmt: etwa 30 MB statt etwa 50 MB.

## Kontrollfragen

1. Warum ist Windows PE seit Windows 10, Version 1809, ein Add-on zum ADK?
2. Was geschieht beim Start von Windows PE mit `startnet.cmd` und `wpeinit` (Ablauf nicht bestätigt), und warum bekommt `CL01` danach eine Adresse?
3. Was unterscheidet Index und Name in der Ausgabe von `/Get-ImageInfo`, und warum exportiert man eine Edition, statt die ganze Datei zu kopieren?
4. Welche der Formate WIM, VHDX und FFU sind dateibasiert, welche sektorbasiert, und welche lassen sich laut Learn auf kleinere Datenträger anwenden?
5. Warum würde der Test mit Nullbytes ein falsches Ergebnis liefern?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand:** ADK und WinPE-Add-on installiert (Versionen notiert), `E:\Images\WinPE-Basis.iso` startet `CL01`, `CL01` bekommt eine Adresse aus dem Bereich, `E:\Images\W11-ENT-Basis.wim` enthält genau die Enterprise-Edition, Testergebnis der Einfachspeicherung dokumentiert.

**Teil 1:** Für Windows 11 26H2 und 25H2 das ADK 10.1.26100.9457 (laut ADK-Seite unterstützt es 26H2, 25H2, 24H2 und Windows Server 2025/2022). Für 26H1 das ADK 10.1.28000.3481; mit Configuration Manager 2609 ist es **nicht als unterstützt belegt** (siehe Modul 01).

**Teil 4 (Referenzwerte aus `wimlib-imagex` 1.14.4, keine DISM-Werte):** `s1` und `s2` je etwa 25 001 514 Byte, beide als zwei Indizes in einer Datei 30 003 610 Byte, zwei getrennte Dateien zusammen 50 003 028 Byte. Ersparnis rund 20 MB oder 40 %: die gemeinsame Datei `common.bin`, die nur einmal gespeichert wird. Anwenden von Index 2 ergab einen mit dem Quellordner identischen Inhalt; der Export von Index 2 ergab eine Datei mit einem Abbild (25 001 514 Byte). Mit Nullbytes: Alle Nulldateien sind Duplikate, die Datei wäre viel kleiner. Mit DISM weichen die Zahlen ab, die Größenordnung (30 MB gegen 50 MB) muss stimmen.

**Kontrollfragen**

1. Weil WinPE unabhängig vom ADK-Kern aktualisiert wird; das Add-on wird getrennt installiert und passend zum ADK gewählt.
2. `wpeinit` initialisiert Netzwerk und Treiber (Plug and Play), `startnet.cmd` startet es und danach die Eingabeaufforderung (Ablauf nicht bestätigt). Danach hat die Netzwerkkarte einen Treiber und fragt per DHCP an.
3. Der Index nummeriert die Abbilder in der Datei, der Name beschreibt sie. Der Export schreibt nur eine Edition in eine eigene, kleinere Datei und lässt nicht benötigte Editionen weg.
4. WIM ist dateibasiert, VHDX und FFU sind plattenbasiert (FFU sektorbasiert). Laut Learn lässt sich ein WIM auf kleinere Datenträger anwenden, ein FFU nicht (Seite *WIM vs. VHD vs. FFU*).
5. Gleich große Nulldateien sind untereinander identisch: Die Einfachspeicherung würde alle zu einer Datei zusammenfassen und das Ergebnis wäre kaum mit echten Daten vergleichbar.

</details>
