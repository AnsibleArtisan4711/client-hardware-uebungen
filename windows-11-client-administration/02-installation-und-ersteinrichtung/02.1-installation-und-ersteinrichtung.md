## Lernziele

Nach dieser Übung kannst du

- eine Generation-2-VM mit virtuellem TPM und Secure Boot für Windows 11 anlegen,
- Windows 11 installieren und die Ersteinrichtung (lokales Administratorkonto, Computername) durchführen,
- Netzwerkadresse, Computername und Zeitzone per Einstellungen und PowerShell setzen,
- einen Prüfpunkt anlegen und erklären, wofür er sich eignet und wofür nicht.

## Voraussetzungen

- Modul 01 abgeschlossen.
- Hyper-V-Host mit Windows 11 Pro oder Enterprise, Hyper-V aktiviert, mindestens 16 GB RAM, 150 GB frei (Annahme des Lehrplans).
- ISO-Datei Windows 11 Enterprise (Evaluation) aus dem Microsoft Evaluation Center. Aktuelle Version, Laufzeit und Verfügbarkeit sind *nicht geprüft*. Notiere, welche Version du verwendest.
- Der Domain Controller `DC01` ist vorbereitet (Adresse `10.50.0.10/24`, Prüfpunkt `DC-Basis`). Er wird ab Modul 05 gebraucht.

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Generation 2** | VM-Typ von Hyper-V mit UEFI-Firmware. Windows 11 braucht UEFI, Secure Boot und TPM. |
| **Virtuelles TPM (vTPM)** | Von Hyper-V bereitgestelltes TPM der VM. Es ist die Voraussetzung für BitLocker in Modul 07. |
| **OOBE** | Out-of-Box Experience, die Ersteinrichtung nach der Installation. |
| **Prüfpunkt (Checkpoint)** | Gespeicherter Zustand einer VM, auf den du zurückspringen kannst. |
| **Privater Switch** | Virtueller Switch ohne Verbindung zum Host oder zu physischen Netzen. Nur VMs am selben Switch sehen sich. |

## Testumgebung

| Gerät | Rolle | Adresse |
|---|---|---|
| Host | Hyper-V | beliebig |
| DC01 | Domain Controller (vorbereitet) | 10.50.0.10/24 |
| CL01 | Windows 11 Enterprise, wird in dieser Übung gebaut | 10.50.0.21/24 |

Switch: privat, `vSwitch-Lab`, Netz `10.50.0.0/24`, ohne Gateway, ohne Internet.

## Aufgabe

### Teil 1: VM anlegen

*(Lerneinheit 2.1, Praxisaufgabe 1)*

**1. Switch anlegen, falls noch nicht vorhanden**

Menüweg: *Hyper-V-Manager → Manager für virtuelle Switches → Neuer virtueller Netzwerkswitch → Privat → Switch erstellen*, Name `vSwitch-Lab`. PowerShell (als Administrator):

```powershell
New-VMSwitch -Name 'vSwitch-Lab' -SwitchType Private
```

**2. VM erstellen**

Menüweg: *Hyper-V-Manager → Aktion → Neu → Virtueller Computer*. Wähle Generation 2, Name `CL01`, Arbeitsspeicher 4096 MB, Netzwerk `vSwitch-Lab`, neue virtuelle Festplatte 80 GB (dynamisch), Installation von ISO-Datei. PowerShell:

```powershell
New-VM -Name 'CL01' -Generation 2 -MemoryStartupBytes 4GB -SwitchName 'vSwitch-Lab' `
       -NewVHDPath 'D:\Hyper-V\CL01\CL01.vhdx' -NewVHDSizeBytes 80GB
Set-VMProcessor -VMName 'CL01' -Count 2
Add-VMDvdDrive -VMName 'CL01' -Path 'D:\ISO\Win11-Enterprise-Eval.iso'
```

Pfade sind Beispiele, passe sie an. Die Parameter stammen aus dem Kenntnisstand (*nicht bestätigt*).

**3. Secure Boot und vTPM aktivieren**

Menüweg: *Rechtsklick auf CL01 → Einstellungen → Sicherheit*, Haken bei *Sicheren Start aktivieren* und *Trusted Platform Module aktivieren*. PowerShell:

```powershell
Set-VMFirmware -VMName 'CL01' -EnableSecureBoot On
Set-VMKeyProtector -VMName 'CL01' -NewLocalKeyProtector
Enable-VMTPM -VMName 'CL01'
Get-VMFirmware -VMName 'CL01' | Select-Object SecureBoot
```

Erwartet: `SecureBoot` zeigt `On` (*sinngemäß*). Stelle zusätzlich sicher, dass das DVD-Laufwerk in der Startreihenfolge vor der Festplatte steht (*Einstellungen → Firmware*).

**4. Dokumentieren**

Mache einen Screenshot der Einstellungen (Generation, Prozessoren, Arbeitsspeicher, Festplatte, Sicherheit, Netzwerk) und lege ihn in deine Dokumentationsablage.

### Teil 2: Windows installieren

*(Lerneinheit 2.2, Praxisaufgabe 2)*

**1. Starten und installieren**

Starte die VM (*Verbinden → Starten*), drücke bei der Meldung *Press any key to boot from CD or DVD* eine Taste (*Meldung nicht bestätigt*). Wähle Sprache, die Edition **Windows 11 Enterprise**, *Benutzerdefiniert* und die 80-GB-Platte.

**2. Ersteinrichtung (OOBE) abschließen**

Lege das **lokale Konto `labadmin`** an. Das Kennwort vergibst du selbst und trägst es **nicht** in diese Dokumentation ein, sondern in deine Kennwortablage.

Verlangt die Ersteinrichtung Internet oder ein Microsoft-Konto (*nicht bestätigt* für deine Version), gehst du so vor:

1. Fahre die VM bei Bedarf herunter.
2. Verbinde den Netzwerkadapter vorübergehend mit einem externen Switch (*Einstellungen → Netzwerkkarte → Virtueller Switch*).
3. Schließe die Einrichtung mit dem lokalen Konto ab.
4. Stelle den Adapter wieder auf `vSwitch-Lab` um.

Notiere, an welcher Stelle der Einrichtung die Verbindung nötig war.

> [!NOTE]
> Solange CL01 am externen Switch hängt, ist das Labor nicht mehr privat. Halte diese Zeit kurz und installiere keine Updates, die du später nicht erklären kannst.

### Teil 3: Grundkonfiguration

*(Lerneinheit 2.3, Praxisaufgabe 3)*

Melde dich als `labadmin` an. Öffne *Windows PowerShell* als Administrator.

**1. Netzwerkadresse**

Menüweg: *Einstellungen → Netzwerk und Internet → Ethernet → IP-Zuweisung → Bearbeiten → Manuell* (Menünamen *nicht bestätigt*). PowerShell:

```powershell
Get-NetAdapter
New-NetIPAddress -InterfaceAlias 'Ethernet' -IPAddress 10.50.0.21 -PrefixLength 24
Set-DnsClientServerAddress -InterfaceAlias 'Ethernet' -ServerAddresses 10.50.0.10
```

Der Schnittstellenname kann abweichen (`Get-NetAdapter` zeigt ihn). Es gibt **kein Gateway**, das Labor hat keinen Router.

**2. Zeitzone**

Menüweg: *Einstellungen → Zeit und Sprache → Datum und Uhrzeit → Zeitzone*. PowerShell:

```powershell
Set-TimeZone -Id 'W. Europe Standard Time'
Get-TimeZone
```

Der Zeitzonenname `W. Europe Standard Time` ist *nicht bestätigt*. `Get-TimeZone -ListAvailable` zeigt alle gültigen Namen.

**3. Computername**

Menüweg: *Einstellungen → System → Info → Diesen PC umbenennen*. PowerShell:

```powershell
Rename-Computer -NewName 'CL01' -Restart
```

**4. Erreichbarkeit prüfen**

Starte `DC01` und prüfe nach dem Neustart von CL01:

```powershell
ping 10.50.0.10
Test-NetConnection -ComputerName 10.50.0.10
```

Die Antwort auf Ping kann durch die Firewall blockiert sein (*nicht bestätigt*). Dokumentiere das Ergebnis, umgehe es aber nicht, bevor Modul 08 behandelt ist.

**5. Gerätedaten wie in Modul 01**

Wiederhole Version, Edition, `Get-Tpm` und `Confirm-SecureBootUEFI` auf CL01 und notiere sie.

### Teil 4: Prüfpunkt

*(Lerneinheit 2.4, Praxisaufgabe 4)*

Fahre CL01 sauber herunter. Menüweg: *Rechtsklick auf CL01 → Prüfpunkt*. PowerShell:

```powershell
Checkpoint-VM -Name 'CL01' -SnapshotName 'CL01-M2-Ende'
Get-VMCheckpoint -VMName 'CL01'
```

Beschreibe in drei Sätzen, warum ein Prüfpunkt keine Datensicherung ersetzt.

## Hinweise

- Windows 11 in einer VM verlangt Generation 2, Secure Boot und vTPM. Eine Generation-1-VM lässt sich nicht nachträglich umstellen, du müsstest eine neue VM bauen.
- Der private Switch ist Absicht: Er schützt dein Heimnetz vor Experimenten, und DC01 samt CL01 sehen sich trotzdem.
- Das virtuelle TPM ist an den Host gebunden (lokaler Schlüsselschutz). Eine VM mit BitLocker lässt sich später nicht ohne Weiteres auf einem anderen Host starten (*nicht bestätigt*, vor Export und Import prüfen).
- Prüfpunkte speichern den Zustand der virtuellen Festplatte. Sie sind **keine** Sicherung: Gehen die VHDX-Dateien verloren, sind auch die Prüfpunkte weg.

## Kontrollfragen

1. Warum braucht Windows 11 in einer Hyper-V-VM Generation 2?
2. Welche Rolle spielt das virtuelle TPM für spätere Kapitel (BitLocker)?
3. Welche Adresse und welche DNS-Einstellung braucht CL01 für den Domänenbeitritt, und warum?
4. Warum darf `vSwitch-Lab` keine Verbindung zum Heimnetz haben?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Zielzustand**

- `CL01`: Generation 2, 2 vCPUs, 4 GB RAM, 80 GB dynamisch, Secure Boot an, vTPM an, Adapter an `vSwitch-Lab`.
- Windows 11 Enterprise installiert, lokales Konto `labadmin`, Name `CL01`, Adresse `10.50.0.21/24`, DNS `10.50.0.10`, Zeitzone Wien, kein Gateway.
- Prüfpunkt `CL01-M2-Ende` vorhanden.

**Antworten**

1. Windows 11 verlangt UEFI mit Secure Boot und TPM. Hyper-V bietet UEFI, Secure Boot und vTPM nur in Generation 2.
2. BitLocker nutzt das TPM, um den Schlüssel des Systemlaufwerks zu schützen. Ohne vTPM wäre die Modul-07-Übung in der VM nicht wie beschrieben möglich.
3. Adresse `10.50.0.21/24` im Labornetz, DNS auf den Domain Controller `10.50.0.10`. Der Client findet den Domain Controller über DNS-Einträge der Domäne. Zeigt DNS woanders hin, scheitert der Beitritt (siehe Modul 05).
4. Der Switch ist privat, damit Experimente (Dienste, Richtlinien, Verschlüsselung) das Heimnetz nicht beeinflussen und keine Geräte außerhalb des Labors Adressen oder Namen stören.

**Prüfpunkt in drei Sätzen (Beispiel)**

Ein Prüfpunkt hängt an den Dateien der VM und liegt auf demselben Speicher. Fällt die Platte aus oder wird die VM gelöscht, sind Daten und Prüfpunkte zugleich verloren. Eine Datensicherung liegt dagegen getrennt und lässt sich einzeln zurückspielen.

</details>
